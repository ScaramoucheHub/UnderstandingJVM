public class JvmComprehension {

    public static void main(String[] args) {
        int i = 1;                      // 1
        Object o = new Object();        // 2
        Integer ii = 2;                 // 3
        printAll(o, i, ii);             // 4
        System.out.println("finished"); // 7
    }

    private static void printAll(Object o, int i, Integer ii) {
        Integer uselessVar = 700;                   // 5
        System.out.println(o.toString() + i + ii);  // 6
    }
}
При старте JVM (до запуска пользовательского кода) Bootstrap ClassLoader сразу загрузит классы Object и String т.к. они нужны для работы самой JVM.
При загрузке классов их метаданные (название класса, статические переменные, константы, данные методов и др.) загружаются в область памяти Metaspace.

При запуске метода main этой программы Application ClassLoader пытается загрузить класс  JvmComprehension. Сперва он делегирует загрузку класса Platform ClassLoader, а тот делегирует загрузку Bootstrap ClassLoader.  Bootstrap ClassLoader ищет эти классы в java.base. Класса  JvmComprehension в  java.base нет, поэтому Bootstrap ClassLoader не может его загрузить и передает управление  Platform ClassLoader. Тот пытается найти класс  JvmComprehension в расширениях Java SE, но не находит его и не может загрузить.  Дальше управление возвращается  Application ClassLoader который ищет  JvmComprehension среди пользовательских классов и загружает его.
Метаданные JvmComprehension также загружаются в область памяти Metaspace.

Дальше будет выполнен запуск статического метода main класса JvmComprehension. В стэке будет создан первый фрейм для метода main:
	Строка №1. int i = 1;  
В стэке (фрейме main) будет создана переменная i типа int и инициализирована значением 1.
	 Строка №2. Object o = new Object();
В стэке (фрейме main) будет создана ссылочная переменная o типа Object. Затем будет выполнен оператор new - в куче будет выделено место для нового объекта типа Object. Дальше будет запущен конструктор без параметров класса Object. При запуске конструктора в стэке будет создан новый фрейм. После того, как конструктор завершит свою работу его фрейм будет закрыт, а в переменную o будет записана ссылка, указывающая на созданный в куче объект.
	Строка №3. Integer ii = 2; 
В стэке  будет создана ссылочная переменная ii типа Integer, но новый объект этого типа создаваться не будет. По умолчанию в Java закэшированы объекты этого типа со значениями от -128 до 127. Ссылка на объект типа Integer со значением 2 будет взята из кэша и записана в переменную ii.
	Строка №4. printAll(o, i, ii);
В стэке создается новый фрейм для метода  printAll и в него копируются значения переменных o, i, ii.
	Строка №5. Integer uselessVar = 700; 
В стэке будет создана ссылочная переменная uselessVar типа Integer. Т.к. значение 700 > 127, то взять значение из кэша не получится и будет создаваться новый объект в куче.  Будет выполнен оператор new - в куче будет выделено место для нового объекта типа Integer. Дальше будет запущен конструктор класса Integer с параметром 700. При запуске конструктора в стэке будет создан новый фрейм. Конструктор проинициализирует новый объект значением 700 и завершит свою работу (его фрейм будет закрыт), а в переменную uselessVar будет записана ссылка, указывающая на только что созданный объект.
	Строка №6. System.out.println(o.toString() + i + ii);
В стэке создается новый фрейм для метода  System.out.println и в него передается строковое значение полученное конкатенацией строк o.toString() + i + ii (что-то вроде java.lang.Object@15aeb7ab12). Это значение будет выведено в консоль. Затем метод  System.out.println будет завершен и его фрейм в стэке будет закрыт.
После этого метод  printAll также будет завершен и его фрейм в стэке тоже будет закрыт.
После завершения метода printAll не останется ссылок на объект uselessVar и он может быть удален сборщиком мусора.
	Строка №7. System.out.println("finished"); 
В стэке снова создается новый фрейм для метода  System.out.println и в него передается строковое значение "finished". Это значение будет выведено в консоль. Затем метод  System.out.println будет завершен и его фрейм в стэке будет закрыт.
Т.к. это последняя инструкция в main, то метод main тоже будет завершен, а его фрейм в стэке закрыт. 

После завершения метода main не останется ссылок на объекты o и ii, и они могут быть удалены сборщиком мусора. Но скорее всего сборщик мусора не будет запущен, т.к. после закрытия main JVM начнет процесс завершения работы (Shutdown). В рамках этого процесса JVM выполнит финальную зачистку ресурсов, но это уже не работа сборщика мусора по освобождению кучи, а подготовка к выгрузке самой виртуальной машины.
